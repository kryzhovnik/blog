# Где рельсы хранят csrf-токены?

TLDR: csrf-токены хранятся в сессии: `session[:_csrf_token]`; в rails >= 4.2 csrf-токены на клиенте обновляются при каждом показе страницы, но это просто замаскированный через XOR токен из сессии.

## Что такое Cross-Site Request Forgery (CSRF)

Это такая атака:

1. Вы залогинены на good-site.com (вы всегда залогинены на многих хороших сайтах)
2. Вы загрузили страницу на evil-site.com
3. Страница на evil-site.com незаметно для вас формирует и отправляет на good-site.com запрос на удаление вашего аккаунта https://good-site.com/account/destoy
4. Поскольку вы залогинены на good-site.com, запрос аутентифицируется и исполняется - ваш аакаунт удален!

## Как от нее защищаются?

Чтобы сделать такую атаку невозможной, используют csrf-токены. Это длинные строки уникальные для каждой сессии на сайте. Клиент (код в браузере) добавляют к каждому не-GET запросу (т.е. к тем которые могут изменять состояние системы) этот токен. Тогда сервер, прежде чем исполнить запрос, сравнивает полученный токен с токеном в текущей сессии.

## Как рельсы реализуют эту защиту?

_В общих чертах:_

1. Формируют уникальный токен для каждой сессии

```ruby
session[:_csrf_token] ||= SecureRandom.base64(AUTHENTICITY_TOKEN_LENGTH)
```

2. Вставляет в форму запросы скрытое поле с этим токеном:

2.1 Для форм, созданных через `form_for` или `form_tag` вставляет это скрытое поле прямо при рендеринге формы на сервере

```html
<input type="hidden" name="authenticity_token" value="DB9fbHNOeLZSFc7XJEG0DERO0uOOcxdKF+uc4BDrwFVFJgRkdFUt/rNKVP0QgUz8wRftrYsUG/T9kd6ivbju/g==">
```

2.2 Для ajax-запросов и тех случаев, когда форма создается на лету в браузере: в <head>-страницы вставляется хелпер `<%= csrf_meta_tag %>`, который генерирует мета тег со значением текена:

```html
<meta name="csrf-param" content="authenticity_token">
<meta name="csrf-token" content="DB9fbHNOeLZSFc7XJEG0DERO0uOOcxdKF+uc4BDrwFVFJgRkdFUt/rNKVP0QgUz8wRftrYsUG/T9kd6ivbju/g==">
```

Это значение уже можно выдернуть через JS (что и делает, например, `jquery_ujs`)

## Диалоги

Q: Так где же хранятся эти токены?

— В сессии!

```ruby
session[:_csrf_token] ||= SecureRandom.base64(AUTHENTICITY_TOKEN_LENGTH)
```

Q: А в чем смысл? Ведь сессия по-умолчанию в рельсах хранится в куках, а значит она доступна на клиенте.

— Не доступна. Рельсы шифруют сессию на сервере, поэтому ее данные доступны только на сервере.

Q: А как так получается, что начиная c Rails 4.2 при заждой загрузке страницы строка-токена в браузере обновляется?

— Это правда, в браузере при каждой новой загрузке страницы токен обновляется, но каждый обновленный токен лишь отображение единственного настоящего токена, который хранится в сессии. Обновление токена не повышает безопасность защиты от CSRF атаки, а необходимо для смягчения угрозы совершенно [другой атаки](http://breachattack.com/). Обновленный токен делается таким образом, чтобы он не был похож на оригинал, но оригинал можно было получить из самого токена.


```ruby
# https://github.com/rails/rails/blob/4-2-stable/actionpack/lib/action_controller/metal/request_forgery_protection.rb#L266-L271
def masked_authenticity_token(session)
  one_time_pad = SecureRandom.random_bytes(AUTHENTICITY_TOKEN_LENGTH)
  encrypted_csrf_token = xor_byte_strings(one_time_pad, real_csrf_token(session))
  masked_token = one_time_pad + encrypted_csrf_token
  Base64.strict_encode64(masked_token)
end
```

На пальцах, маскировка:

```
замаскированный_токен = рандом + (рандом XOR настоящий_токен)
```

размаскировка:

```
рандом = первая половина от замаскированный_токен
настоящий_токен = (вторая половина от замаскированный_токен) XOR рандом
```
